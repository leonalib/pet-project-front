# Моя полка

Небольшая личная библиотека на **React + TypeScript + MUI**. Добавляйте книги, выбирайте статус чтения и оставляйте заметки. Список сохраняется в браузере отдельной кнопкой.

## Запуск

Нужен Node.js 24. Проект использует npm и зафиксированные версии зависимостей в package-lock.json.

```sh
git clone https://github.com/leonalib/pet-project-front.git
cd pet-project-front
npm ci
npm run dev
```

Откройте адрес из терминала, обычно http://127.0.0.1:5173. Чтобы загрузить ранее сохранённую полку, используйте тот же браузер и адрес: хранилище привязано к origin, включая порт; localhost и 127.0.0.1 имеют разные хранилища.

## Как пользоваться

1. Введите название книги и автора. Выберите статус; заметка необязательна.
2. Нажмите **«Добавить»**: книга появится на странице, поля очистятся.
3. Нажмите **«Сохранить»**: текущий список запишется в localStorage.
4. Обновите страницу: список снова будет пустым, потому что React state создаётся заново.
5. Нажмите **«Загрузить»**: сохранённые книги снова появятся.

Автосохранения и автоматической загрузки нет: это намеренное поведение учебного задания. До добавления книги и после успешного сохранения кнопка «Сохранить» отключена. Загрузка заменяет весь текущий список сохранённым; несохранённые изменения будут потеряны, о чём интерфейс предупреждает.

Книги хранятся только в этом браузере, без сервера и аккаунта. Сохранение списка не сохраняет незавершённые поля формы. Очистка данных сайта удаляет сохранённую полку.

## Что происходит в коде

**State** — данные в памяти React. Форма хранит введённые значения в `draft`, а `App` хранит массив `books`. Вызов `setBooks` обновляет данные и заставляет React перерисовать список.

**localStorage** — хранилище браузера, принимающее строки. `saveBooks` преобразует данные в JSON, `loadBooks` читает JSON и проверяет его структуру перед передачей в React.

```text
Ввод → state формы → «Добавить» → state списка → карточки
                                     ↓
                                «Сохранить»
                                     ↓
                                 localStorage
                                     ↓
                                 «Загрузить» → state списка → карточки
```

`handleAddBook` добавляет книгу через функциональное обновление `setBooks`. `handleSaveBooks` сохраняет текущий массив. `handleLoadBooks` меняет массив только после успешной проверки прочитанного значения.

Ключ: `my-bookshelf:v1`. Формат: `{ version: 1, books: [...] }`. Каждая книга содержит `id`, `title`, `author`, `status`, `notes`. Статусы: `planned`, `reading`, `finished`. Валидация проверяет поля, длины строк, версию и уникальность идентификаторов. Ошибки хранилища показываются на странице, а текущий список сохраняется в памяти.

## Структура

| Файл                               | За что отвечает                              |
| ---------------------------------- | -------------------------------------------- |
| `src/App.tsx`                      | Список в state и обработчики кнопок          |
| `src/components/BookForm.tsx`      | Поля MUI, state формы, обязательные значения |
| `src/components/BookList.tsx`      | Карточки книг и пустое состояние             |
| `src/types/book.ts`                | Типы, статусы и ограничения полей            |
| `src/storage/booksStorage.ts`      | Чтение, запись и проверка localStorage       |
| `src/theme.ts`                     | Цвета, шрифты и компоненты темы MUI          |
| `src/main.tsx`                     | Запуск React и подключение темы              |
| `src/App.test.tsx`                 | Сценарии использования формы и кнопок        |
| `src/storage/booksStorage.test.ts` | Проверки хранилища и ошибок                  |

Шрифт Golos Text установлен локально через Fontsource: браузеру не нужно обращаться к стороннему сервису шрифтов. Сервер, авторизация, поиск, редактирование и удаление книг в эту учебную версию не входят.

## Проверки

```sh
npm run check
```

Команда проверяет форматирование, ESLint, все тесты, TypeScript и производственную сборку. Отдельные команды:

| Команда                | Назначение                                       |
| ---------------------- | ------------------------------------------------ |
| `npm run dev`          | Разработка с обновлением страницы                |
| `npm run lint`         | ESLint: типы, хуки, мутации, циклические импорты |
| `npm run typecheck`    | Полная проверка обоих TypeScript-проектов        |
| `npm test`             | Все тесты один раз                               |
| `npm run test:watch`   | Тесты при изменениях                             |
| `npm run format`       | Форматирование Prettier                          |
| `npm run format:check` | Проверка форматирования                          |
| `npm run build`        | Типы и сборка в dist/                            |
| `npm run preview`      | Просмотр готовой сборки                          |

Тесты покрывают обязательные поля, статусы, заметки, ручное сохранение и загрузку, повторную загрузку без дубликатов, отсутствие автосохранения, перезапуск, повреждённый JSON, неизвестный формат, дубликаты id и недоступное/переполненное хранилище.

## Как изменения попадают в main

Работа по [задаче #1](https://github.com/leonalib/pet-project-front/issues/1) идёт в `feature/1-bookshelf`.

1. Изменения делаются в feature-ветке, затем просматривается полный diff.
2. В коммит добавляются конкретные файлы. Husky запускает lint-staged (форматирование и ESLint), затем полную проверку типов.
3. Ветка отправляется на GitHub и открывается Pull Request в main.
4. GitHub Actions повторяет `npm run check` на Node.js 24.
5. После ревью и успешных проверок PR объединяется в main.

Правила проекта сохранены в AGENTS.md. Хуки не обходятся. Для синхронизации собственной работы используется `git pull --rebase`; опубликованная общая история не переписывается.
